OpenAI Codex 用了一段时间，把上手过程中觉得好用、容易踩坑的地方整理成一篇实用向清单。

按「文件操作与权限 → 命令行 → 记忆 → 计划与引导 → 插件 → Skills/MCP → 自动化 → 两个并行开发实践」的顺序来写。

---

## 一、本地文件操作：先管好权限

### 新建项目

打开一个项目目录即可开始，既能从列表里新建项目，也能直接选择本地文件夹。

### 三种权限模式

| 权限模式   | 行为                                                                 | 适合场景                     |
| ---------- | -------------------------------------------------------------------- | ---------------------------- |
| 请求批准   | 只能读写所选文件夹内的文件，访问文件夹外内容时单独申请权限           | 默认、只读浏览、谨慎操作     |
| 替我审批   | 权限更高。AI 自动检查操作是否存在风险，有风险就请示，无风险直接执行 | 日常开发，效率与安全的平衡点 |
| 完全访问   | 在电脑上执行任意操作，不做任何请示                                   | 自己有把握、追求全自动       |

建议日常选「替我审批」：既能放权让它跑，又给高风险操作留了一道人工闸门。

### 项目内任务多开

支持在同一个项目里额外开启并行的对话任务，多个任务互不阻塞。

---

## 二、用命令行干活，配一个 Agent IDE

开启「替我审批」后，Codex 可以直接在终端里开展工作。你不用敲命令，用日常语言就能让它帮你安装各类工具：

1. Cursor / VSCode 这类编辑器软件
2. Claude Code、OpenClaw 这类通用 Agent 命令行
3. Node 环境与依赖
4. Agent 自己会常用的 skills、MCP、CLI 配置

### 一个已知的坑：结果文件无法直接编辑

目前「聊天任务框」里列出的文件，可以在右侧「结果框」里打开，但**没法直接编辑**。

**解决办法**：装一个「Agent IDE」（带 AI 能力的编辑器），Codex 会识别并把它挂到界面上。以 Cursor 为例：

1. 用日常语言让 Codex 在系统里部署好 Cursor；
2. 部署好后，Cursor 常驻在右上角；
3. 之后结果里的文件都能在 Cursor 里打开直接编辑。

## 三、持久记忆：三级记忆体系

### 方式一：全局级长期记忆（Global AGENTS.md）

「全局生效 AGENTS.md」会在任何项目里作为上下文喂给模型，适合记录所有任务都通用的规则——比如你的使用习惯、工作偏好。

- 在「设置 → 个性化」的「自定义指令」里添加规则；
- 也可以在聊天任务里用日常语言交代规则，最后要求它同步到全局 AGENTS.md。

### 方式二：项目级持久记忆（Project AGENTS.md）

只在固定项目内生效，适合放这个仓库专属的约定。

- 在项目中新建一个文件，命名为 `AGENTS.md`（注意大写）；
- 用自然语言写清项目规则；
- 也可以在对话里交代规则后，让 Codex 写进项目 AGENTS.md。

### 方式三：自动记忆

Codex 会在你结束对话、闲置一段时间之后，把之前的对话总结成记忆，并在后续对话与项目中自动复用。

- 在「设置 → 个性化」中找到「启用记忆」打开；
- 记忆文件一般落在 `~/.codex/memories` 目录下，随时可以翻看或清理。

## 四、计划模式 + 目标模式：想清楚再执行

针对有一定复杂度、或自己都还没想清楚的项目，可以开启**计划模式**，让 Codex 引导你把想法补成可执行的计划，再开始动手。搭配 brainstorming 类的提示先把需求聊透，效果更好。

大致流程：

1. 打开项目文件夹，开启「计划模式」；
2. 顺着 Codex 的引导选择或输入提示词，把方案补全；
3. 计划生成后还可以自己给建议、调整计划；
4. 开始执行后如果中途有不满意的点，可以随时提交一条临时建议（比如「只重构主入口文件，弹窗只做类型衔接、保持行为不变」），在合适时机点「引导」提交，**执行过程不会被中止**；
5. 执行中有些想法拿不准，可以用「fork（分叉）」开个副本单独试，不弄乱主线任务；
6. 对生成结果可以在预览界面用「注释」批注，批注后发给 Codex 修改；
7. 项目完结后，可以让 Codex 基于这次项目生成一份项目级 AGENTS.md，沉淀成可复用的上下文。

## 五、插件：给 Codex 一双眼睛和手

### 三个重点插件

| 插件          | 作用                                               | 适用场景                                                     |
| ------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| Browser       | 操作 Codex **内置浏览器**                          | 自动化测试公开网页、本地预览、无需登录的页面                   |
| Computer Use  | 操控**所有电脑软件**，相当于多了眼睛 + 鼠标         | 命令行或插件搞不定的场景、纯图形界面交互的场景                 |
| Chrome        | 控制**真实的 Chrome 浏览器**在后台执行浏览器操作    | 必须登录真实网站才能完成的浏览器任务，不会接管你正在用的窗口   |

### 五个拿来即用的用例

下面几条是可照抄或改写的 Prompt 思路，以 Web 页面为例；把 URL / 页面换成你自己的项目即可。

**案例 1：页面很卡，定位耗时**

打开本地页面 + Chrome DevTools，看 Performance，找出最大耗时，检查是否存在：

- 重复 Render
- Layout Thrashing（强制同步布局）
- 长任务（Long Task）
- Memory Leak

**案例 2：UI 回归测试**

用 desktop / tablet / mobile 三种宽度浏览首页，逐项检查：

- 是否有横向滚动
- 是否出现 Layout Shift
- Button 是否超出容器
- Header Sticky 是否正常

发现问题就让 Codex 直接改代码并重新验证。

**案例 3：Console Error 自动修复**

打开页面 → 看 Console → 修复所有 Error；Warning 若会影响生产也一并修掉。

**案例 4：页面基础功能检查**

打开本地页面，逐项确认按钮能点、表单能提交、跳转正常、样式没有明显错位。

**案例 5：桌面软件控制（Computer Use）**

让插件直接打开某个软件，按你的描述复现问题、排查或修改 Bug——尤其适合纯 GUI 操作、命令行到不了的地方。

> 注意：若要在公司内部系统上复现，记得处理好登录态与数据脱敏。

## 六、Skills 与 CLI：能力即插即用

Skills 和 CLI 的下载链接可以直接丢给 Codex，它会自动下载并在引导下完成部署。社区里有很多公开整理的优秀 Skill 合集，也可以按自己工作流**创建专属 Skill**——把反复要做的步骤沉淀成一个可复用命令，比每次重新描述高效得多。

---

## 七、MCP：接入外部能力

Codex 支持 MCP（Model Context Protocol）。把常用的 MCP Server 配置挂上去，就能让 Agent 直接调用外部服务与数据，减少来回手抄。个人直接用社区公开的 MCP 服务即可；团队内部也可以维护自己的私有市场，把常用数据源统一收口。

---

## 八、自动化任务

日常重复的巡检类工作可以交给自动化：

- **自动化面板**：新建自动化，或从需求相近的官方样例改起，完成设置后按计划触发；
- **日常语言交互设置**：直接在对话框用自然语言描述「每天几点做什么」，让 Codex 帮你设置成自动化任务。

## 实践一：Codex + Git Worktree 并行开发

### Git Worktree 是什么

Git Worktree 是 Git 官方能力，让**一个仓库同时拥有多个独立工作目录**。每个 Worktree：

- 对应一个独立目录，可检出不同分支；
- 拥有独立的工作区与未提交修改；
- 共享同一份 Git 对象库，几乎不额外占空间。

一句话：一个 Git 仓库，多个独立开发环境。

### 典型场景

1. **并行开发多个需求**：几个需求完全隔离、互不干扰，各自的上下文完整保留，随时切换。
2. **紧急 Bug 修复**：Feature 开发到一半不想 stash / commit 临时代码，另开一个 Worktree 切到 hotfix 分支修线上问题，修完删掉即可，不污染原开发现场。
3. **方案对比实验**：不确定哪种实现更好，两个方案各开一个 Worktree 同时尝试。
4. **Code Review / 调试**：Review 某个 PR 不用切换当前工作区，为对应分支单独建 Worktree 独立运行验证。

### 在 Codex 里怎么用

在项目中打开命令菜单选择「派生（Fork）」，有两个选项：

- **派生到新工作树中继续** → 对应创建新的 Git Worktree；
- **在新的线程中继续** → 只开新对话线程，不建工作树。

选择前者后，Codex 会自动创建新的 Worktree、分配独立工作目录、在界面显示新工作树节点并切过去。注意它不是在复制项目目录，而是基于当前 Git 仓库新建工作目录，由 Git 统一管理对象库与版本信息。此时项目会形成两个独立环境：**主工作树**（当前本地目录）与**分支工作树**（开发新功能 / 实验）。

推荐流程：

1. 从主工作树派生新 Worktree；
2. 在新 Worktree 里完成功能开发并验证；
3. 为修改创建新的 Git Branch；
4. 把该 Branch 合并回主分支；
5. 主工作树同步最新代码，完成集成。

## 实践二：多线程 Agent Teams 自动协作

核心理念：**当前线程当「领导」，多个 Worker 线程并行实现**。线程之间可以协作，但必须有明确的责任边界与汇报协议，避免并行失控。

### 1. 职责解耦

把一次研发拆成多个单一职责的 Agent（比如 Planning Agent 负责规划、Development Agent 负责实现），避免「规划 + 实现」耦合在同一个 Agent 里。

### 2. 跨线程消息协作

传统做法是人工在两个 Agent 会话之间复制粘贴方案文档、再手动触发开发。引入会话控制后，Agent 之间可以直接跨线程通信，把「复制规划 → 触发开发」自动化。

### 3. 自动闭环

开发流程无需人工协调 Agent 之间的交互，形成从接收任务到验收的自动闭环。

### 4. 注册与生命周期管理

每个 Agent 首次加入时完成注册，登记：身份、职责（Role）、会话 ID、Workspace 信息、Work Log 存储位置。其中**会话 ID 是协作体系的核心标识**，用于跨线程通信与上下文定位。

### 5. Work Log 与 Workspace

每个 Agent 有独立工作空间：

- **Work Log**：记录 Agent 全生命周期行为——接收任务、开发记录、修复记录、验收结果、消息往来，形成完整执行轨迹；
- **Workspace**：存放文档、代码、中间产物、开发结果；Agent 之间可以互相读取所需内容，无需人工介入。

> 小建议：并行协作不是越多越好。先从「1 个规划 + 1 个开发」这种小规模试起，确认责任边界和汇报节奏能收住，再扩大并行度。
